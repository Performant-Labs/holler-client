# ADR 0004 — License: AGPL-3.0-or-later, outside PRs now welcome

**Status:** accepted
**Issue:** #5
**Date:** 2026-09-06

## Decision

holler-client switches from `Proprietary` to **AGPL-3.0-or-later** (the FSF's own recommended
boilerplate — "or (at your option) any later version," not `-only`). The full license text is
now at `LICENSE` in the repo root, fetched verbatim from the FSF. `Cargo.toml`'s `license`
field is updated to the real SPDX identifier, `AGPL-3.0-or-later`.

Outside pull requests are now welcome (see `CONTRIBUTING.md`) — previously this project said
explicitly it wasn't taking outside code contributions yet.

This mirrors [holler-server ADR-0016](https://github.com/Performant-Labs/holler-server/issues/17),
applied here independently since each repo's `Cargo.toml`/license is its own axis.

## Why AGPL and not a permissive license

Holler's dependencies mostly use the Rust-ecosystem convention of dual MIT/Apache-2.0
licensing. This project deliberately does **not** follow that convention.

The server README's "Why this is different" comparison argues that self-hosting with no cloud
intermediary at all is a real differentiator against Warp's Remote Control, which routes every
session through Warp's cloud relay regardless of which agent is inside it. A permissive license
does not protect that positioning: anyone could fork Holler, run it as a hosted service, and
offer a closed "Holler Cloud" wrapper without contributing anything back — recreating exactly
the cloud-intermediary model this project exists to avoid, just with someone else's proprietary
layer on top of Holler's own code. That reasoning applies equally to the client half of the
circuit, so both repos make the same choice.

AGPL-3.0's network-use clause closes that gap: a modified version used to provide a network
service must make its source available to the users of that service.

## Consequences

- `LICENSE` (root) is the canonical, verbatim AGPL-3.0 text from the FSF.
- `Cargo.toml`: `license = "AGPL-3.0-or-later"`.
- `README.md`'s "Status and license" section no longer says `Proprietary`.
- `CONTRIBUTING.md`'s "Code contributions" section now welcomes outside PRs: fork → branch →
  PR → CI must pass (`test (ubuntu-latest)` and `test (macos-latest)`, both required by
  branch protection on `main`) → maintainer review. No CLA, no RFC process — kept lightweight,
  matching this project's current scale.
- This does not change [ADR-0003](https://github.com/Performant-Labs/holler-client/issues/4)'s
  versioning policy — an unrelated axis.

## Not decided here

- Whether to eventually publish this crate to crates.io.
- Any change to the wire protocol, versioning policy, or release mechanics.
