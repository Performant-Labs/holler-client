# ADR 0003 — Versioning: SemVer per crate, starting at 0.1.0, independent of holler-server

**Status:** accepted
**Issue:** #4
**Date:** 2026-09-06

## Decision

Circuit-wide policy: [holler-server ADR 0014](https://github.com/Performant-Labs/holler-server/issues/15). This crate follows it directly, with no client-specific carve-out:

- SemVer (`MAJOR.MINOR.PATCH`), starting at **0.1.0** (already the scaffold default — this ADR ratifies it).
- **PATCH** — security fixes and other minor changes (bug fixes, non-behavioral refactors, dependency bumps).
- **MINOR** — new features (a new CLI subcommand/flag, a new capability, anything additive).
- **MAJOR** — anything that breaks backward compatibility.
- No SemVer pre-1.0 carve-out: a breaking change bumps `MAJOR` even at `0.x`, per the server ADR's explicit reasoning.
- **This crate's version moves independently of holler-server's.** A holler-client release implies nothing about holler-server's version. The only version both sides negotiate is the wire protocol (`v`, `protocol_min`/`protocol_max` — [holler-server ADR 0009](https://github.com/Performant-Labs/holler-server/issues/10)), which is a separate axis entirely and does not follow this crate's own release cadence.

## What counts as "breaking" for this client

Same framing as the server ADR, applied to this repo's surfaces:

- The `holler` CLI: removing/renaming a subcommand or flag (`join`/`detach`/`status`/`support`/`caps`/`query`/`run`), changing argument order, changing exit-code semantics.
- `--json`/query-answer output shape (the `status`/`caps`/`support`/`protocol` documents this crate builds and answers over the wire — see issue #30).
- On-disk formats: the persisted credential file (issue #23) and the body/session config file (issue #25). A format change an older binary can't read without migration is breaking.

## Consequences

- `Cargo.toml`'s `version` is this repo's single source of truth; no cross-repo version sync with holler-server.
- A `CHANGELOG.md` starts from this decision forward (not built retroactively).
- Bumps happen at release points, not on every merged PR.
