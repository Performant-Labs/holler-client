# ADR 0005 — Attach mode: client is not parent of the body

**Status:** proposed
**Issue:** #6
**Date:** 2026-09-07

**Circuit policy:** [holler-server#18](https://github.com/Performant-Labs/holler-server/issues/18) (ADR 0017).
**Epic:** [#97](https://github.com/Performant-Labs/holler-client/issues/97) — "Attach to a live OpenCode / Herdr body" (filed in the same batch as [holler-server#254](https://github.com/Performant-Labs/holler-server/issues/254)).
**Amends:** [ADR 0002](ADR-0002.md) ([#3](https://github.com/Performant-Labs/holler-client/issues/3)) — spawn remains default; attach is a second transport in the same config file.

## Decision

`SessionConfig` gains an explicit transport:

| `mode` | Who starts OpenCode | What `shutdown` / `detach` does |
|---|---|---|
| `spawn` (default) | this process, via `command` | tear down the ACP child (v1 today) |
| `attach` | already running (Herdr pane or `opencode serve`) | close HTTP/ACP control channel only |

Attach config (normative shape; implementer may rename fields but not the semantics):

```toml
[[session]]
name = "alpha"
harness = "opencode"
mode = "attach"
endpoint = "http://127.0.0.1:4096"
session_id = "ses_…"          # required in v1 of attach; no silent session/new
# command is ignored in attach mode (do not spawn as a fallback)
```

Rules:

1. **Never `session/new` in attach mode.** If `session_id` is missing or `GET {endpoint}/session/{id}` (or `/api/session/{id}`) 404s, fail closed with a precise error. Do not create a consolation session.
2. **Never parent the TUI.** `AcpDriver::spawn` is not called. No `opencode acp` child. No process-group kill on exit.
3. **Prompt and interrupt go through OpenCode HTTP** on that endpoint (the same surface v1 already uses as interrupt fallback). Probe the paths the installed OpenCode actually serves and pin them in driver comments: interrupt is `POST /session/{id}/interrupt` and/or `POST /api/session/{id}/interrupt`; prompt is the async message/prompt equivalent (`POST /session/{id}/prompt_async` or v2 `POST /api/session/{id}/prompt`). Translate responses into existing `DriverEvent`s.
4. **`SessionManager::shutdown` is transport-aware.** Attach sessions drop channels and return. Spawn sessions keep today's child teardown.
5. **`holler detach` means leave the circuit** (drop WS + local credential). It does not mean kill attached bodies.
6. **Single-instance lock on `holler run` stays.** Two `run` processes attaching the same `session_id` is undefined; fail the second lock as today.
7. **Herdr discovery is optional follow-on**, not required to ship attach. v1 attach: operator pastes `session_id` + endpoint.
8. **Do not implement PTY typing.**

## Code map (today)

- `src/config.rs` — `SessionConfig` has only `name`, `harness`, `command`, `interrupt`.
- `src/acp_driver.rs` — `AcpDriver::spawn` always execs `command`, `initialize`, `session/new`.
- `src/session_manager.rs` — `spawn()` always `AcpDriver::spawn`; `run_session` ends with `driver.shutdown()` which waits for the child.
- `src/connection.rs` — live WS; detach drops the run process.
- Interrupt HTTP fallback already knows `POST {base}/api/session/{id}/interrupt`.

## Consequences

- Attach sessions are "confirmed" when `endpoint` answers (GET session by id), not when `opencode` is on PATH as an ACP argv.
- Tests: fake HTTP OpenCode, not `stub-acp` stdio. Fake OC process still alive after `SessionManager::shutdown`.
- Land `docs/adr/ADR-0005.md` and an index row.
