# ADR 0002 — Bodies are config + ACP subprocess, not plugins

**Status:** accepted  
**Issue:** #3  
**Date:** 2026-09-05

## Decision

This client does **not** grow an in-process plugin API and does **not** vendor a new harness SDK per release.

Circuit policy: [holler-server ADR 0011](https://github.com/Performant-Labs/holler-server/issues/12).

This process:

1. Reads a body config (sessions: name, harness id, `command` argv, optional interrupt).
2. Spawns `command` as ACP stdio (v1 default: `opencode acp`).
3. Answers `query support <harness>` from “is that command runnable,” not from a compiled-in list.
4. If someone needs Claude and `claude-agent-acp` exists, they add a config row. **No holler-client release.**

Out-of-tree adapters (harness does not speak ACP) are **someone else’s binary** on `command`. They must not be `dlopen`ed.

## Consequences

- v1 epic implements the ACP driver + OpenCode default config, not “the OpenCode plugin.”
- Local `holler support opencode` probes PATH / configured argv.
